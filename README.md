# GlobeTrek Adventures — Negombo

Two-portal travel platform:

1. Customer Portal (`GlobeTrek/`)
2. Management Portal (`GlobeTrek_Management/`) with role-based Staff/Admin access.

## Requirements covered

### Customers

- Registration/login with password hashing
- Browse/search active packages
- Package details and itinerary information
- Custom trip booking: date, travelers, accommodation, transport, special requests
- Booking history and status
- PayHere checkout integration (sandbox/live configurable)
- Customer inquiries and conversation history

### Staff

- Dashboard
- Create/update/delete tour packages and package details
- Booking confirmation/cancellation/completion
- Assign bookings to staff
- Internal notes
- Hotel/transport supplier coordination status and notes
- Accommodation and transport catalogue management
- Customer inquiry response workflow

### Admin

- All management capabilities
- Staff/customer account and role management
- Booking oversight
- Sales and demand reports
- Audit log foundation
- Payment oversight
- System settings page

## Installation

1. Create a MySQL database by importing `database.sql`.
2. Configure database and PayHere values through environment variables or the fallback constants in `config.php`.
3. Put both portal folders under the same PHP web root.
4. Ensure PHP 8.1+ with PDO MySQL is enabled.
5. Open `GlobeTrek/` to register the first customer.
6. Create an admin user with the SQL below, replacing the hash with one generated by PHP:
   `php -r "echo password_hash('ChangeMe!123', PASSWORD_DEFAULT), PHP_EOL;"`
7. For PayHere, set `PAYHERE_ENABLED=true`, merchant credentials, and use a public HTTPS `notify_url`. PayHere requires server-side notification checksum verification.

## Production checklist

- HTTPS
- Strong unique DB credentials
- Environment variables/secrets manager
- Restrict database network access
- Backups and monitoring
- Configure PayHere domain approval and webhook URL
- Replace demo credentials immediately
- Configure mail/SMS provider if transactional notifications are required

## Email OTP password reset

Both the customer portal and the staff/admin management portal now include **Forgot password?**.

Flow: email -> 6-digit OTP -> OTP verification -> new password. OTPs expire after 10 minutes, are stored hashed, allow a maximum of 5 verification attempts, and have a 60-second resend cooldown.

### SMTP setup

Copy `.env.example` to `.env` in the project root and configure the `MAIL_*` values. For Gmail, use `smtp.gmail.com`, port `587`, `tls`, your Gmail address, and a Google **App Password** (not your normal Gmail password). The sending address should normally match `MAIL_USERNAME`.

For local UI testing without real email, set `MAIL_DRIVER=log`; generated messages are written to `storage/mail.log`. Do not use log mode in production.

The reset table is created automatically when the feature is first used. `password_reset_migration.sql` is also included for environments where schema changes are deployed manually.
